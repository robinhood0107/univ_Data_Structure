# 첫 번째 코드의 문제점 + 백트래킹 기본 개념

## 백트래킹의 기본 개념

**백트래킹 = 길이 막히면 돌아가기**

```
A → B → C (막혔다!)
       ↓
     mark[C] = 0 (미방문으로 돌려놓음)
       ↓
스택에서 B의 정보 꺼냄
       ↓
B로 돌아가서 다른 방향 시도
```

**핵심:** 막다른 곳에 도달했을 때 **`mark[i][j] = 0`** 한 번만 하면 된다!

---

## 첫 번째 코드의 문제 1: 마크를 두 번 초기화

```cpp
while (!st.empty()) {
    temp = st.top();
    st.pop();
    int i = temp.x;
    int j = temp.y;
    int d = temp.dir;
    
    // ⚠️ 불필요한 것: 스택에서 꺼낼 때 초기화
    mark[i][j] = 0;
    maze[i][j] = 0;
    
    while (d < 8) {
        // ... 탐색 ...
    }
    
    // 🚫 절대 하면 안 되는 것: 이미 초기화했는데 또 함
    mark[i][j] = 0;
    maze[i][j] = 0;
}
```

**1️⃣ 불필요한 것 (해도 되지만 비효율):**
- 스택에서 꺼낼 때 `mark[i][j] = 0;`
- 왜? 어차피 8방향 다 탐색한 후에 초기화하니까
- 결과: 불필요한 연산 증가

**2️⃣ 절대 하면 안 되는 것 (논리 오류):**
- 같은 위치를 두 번 초기화
- 왜? 
  - 백트래킹의 논리가 깨짐
  - 코드 의도가 완전히 불명확
  - 버그 발생 가능성 높음
  - 유지보수 불가능

## 첫 번째 코드의 문제 2: 불필요한 경로 표시

```cpp
if ((maze[g][h] == 0) && (mark[g][h] == 0)) {
    mark[g][h] = 1;
    
    temp.x = i;
    temp.y = j;
    temp.dir = d + 1;
    st.push(temp);
    
    // ⚠️ 불필요한 것: 탐색 중에 경로를 표시
    mark[i][j] = 2;
    maze[i][j] = 2;
    
    i = g;
    j = h;
    d = N;
}
```

**불필요한 것 (해도 되지만 비효율):**
- 탐색 중에 `mark[i][j] = 2;` 로 경로 표시
- 왜?
  - 출구 찾을 때만 경로를 표시하면 됨
  - 탐색 중에 계속 표시하면 불필요한 연산
  - 메모리 낭비
  - 코드 복잡도 증가

**결과:** 효율성 저하, 코드 복잡도 증가

## 두 번째 코드: 올바른 백트래킹

```cpp
if ((maze[g][h] == 0) && (mark[g][h] == 0)) {
    mark[g][h] = 1;                      // 방문했다고 표시 (필요함)
    
    temp.x = i;
    temp.y = j;
    temp.dir = d + 1;
    st.push(temp);                       // 이전 위치 저장 (필요함)
    
    // ✅ 경로 표시 안 함 (필요 없음)
    
    i = g;
    j = h;
    d = N;
}

// 8방향 다 막혔을 때 (백트래킹 발생!)
mark[i][j] = 0;                          // 한 번만 초기화 (필요함)
maze[i][j] = 0;
```

**필요한 것만 한다:**
- 1️⃣ 새 위치 방문 표시 (`mark[g][h] = 1`)
- 2️⃣ 이전 위치 저장 (`st.push(temp)`)
- 3️⃣ 백트래킹 (`mark[i][j] = 0`)

---

## 비효율과 효율의 차이

### 첫 번째 코드 (비효율)
```
스택에서 꺼냄 → 초기화 → 탐색 → 경로표시 → 초기화 → 반복
                ❌         ❌        ❌
        불필요한 연산 3개 추가!
```

### 두 번째 코드 (효율)
```
스택에서 꺼냄 → 탐색 → 반복
    필요한 것만 함!
```

## 정리: 백트래킹의 정확한 흐름

**필요한 초기화는 단 1번:**

```
8방향 모두 막혔을 때
    ↓
mark[i][j] = 0  ← 이것 한 번만!
    ↓
스택에서 이전 위치 꺼냄
    ↓
이전 위치에서 다른 방향 시도
```

이것이 **진정한 백트래킹**입니다!
