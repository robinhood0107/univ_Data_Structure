# Concepts의 간략한 설명
**[2. (Ellipsis, 줄임표) ... 문법과 initializer_list와 함께 실전 응용 방법.md](./2.%20(Ellipsis,%20줄임표)%20...%20문법과%20initializer_list와%20함께%20실전%20응용%20방법.md)에서 ```requires (std::convertible_to<Args, Song> && ...``` 코드에 대한 설명**

질문하신 코드는 \*\*C++20 Concepts(컨셉)\*\*을 **Fold Expression**과 결합해서 사용하는 아주 **세련되고 강력한(Modern C++) 방법**입니다.

이 문법을 하나하나 뜯어서 설명해 드리고, 실제로 어떻게 사용하는지 정리해 드릴게요.

-----

### 1\. 코드 해부: `requires (std::convertible_to<Args, Song> && ...)`

이 코드는 \*\*"템플릿 함수에 들어오는 모든 인자가 `Song` 클래스로 변환 가능해야 한다"\*\*는 조건을 거는 문지기(Security Guard)입니다.

#### ① `requires` (문지기)

  * **역할:** "이 뒤에 나오는 조건이 `true`일 때만 이 함수를 컴파일해라. 아니면 에러를 띄워라."
  * 템플릿의 \*\*제약 조건(Constraint)\*\*을 명시하는 키워드입니다.

#### ② `std::convertible_to<Args, Song>` (검사 기준)

  * **역할:** `Args` 타입이 `Song` 타입으로 바뀔 수 있는지 확인합니다.
  * **의미:** "너 `Song`이 될 수 있어?" (예: `Song`의 생성자가 받는 인자 타입들과 호환되는지 체크)
  * **헤더:** `<concepts>` 필요.

#### ③ `&& ...` (Fold Expression: 단체 검사)

  * 아까 배운 `...` 기억나시죠? 이걸 `&&`(AND 연산자)와 함께 썼습니다.
  * **의미:** "인자가 10개라면, 10개 **모두(AND)** 조건을 만족해야 한다."
  * **확장된 모습:**
    ```cpp
    (convertible_to<Arg1, Song> && convertible_to<Arg2, Song> && convertible_to<Arg3, Song>)
    ```
    👉 하나라도 `Song`으로 변환이 안 되면 **입구 컷**당합니다.

-----

### 2\. 사용 위치와 방법

`requires` 절을 작성하는 위치는 크게 두 군데입니다. 둘 다 똑같이 작동하니 편한 곳을 고르세요.

#### 방법 A: 템플릿 선언 바로 뒤 (가장 많이 씀)

```cpp
#include <concepts> // 필수!

template<typename... Args>
requires (std::convertible_to<Args, Song> && ...) // 여기에 작성
void addSongs(Args... args) {
    // ...
}
```

#### 방법 B: 함수 뒤쪽 (Trailing Requires Clause)

함수 선언이 너무 길어질 때 가독성을 위해 뒤로 뺍니다.

```cpp
template<typename... Args>
void addSongs(Args... args) requires (std::convertible_to<Args, Song> && ...) {
    // ...
}
```

-----

### 3\. 왜 이걸 써야 하나요? (Error Message의 차이)

Concepts의 진가는 **에러 메시지**에서 드러납니다. 일부러 틀린 값을 넣어보면 확연히 다릅니다.

**상황:** `addSongs(10);` // 숫자만 달랑 넣음 (Song 변환 불가)

#### ❌ Concepts 없을 때 (과거)

> *Error: no matching function for call to 'addSongs'... candidate template ignored... substitution failure... enable\_if... (알 수 없는 외계어 100줄 출력)*
>
> 👉 **문제점:** 초보자는 도대체 뭐가 틀린 건지 찾기 힘듭니다. 함수 내부 구현에서 터진 건지 인자가 틀린 건지 헷갈립니다.

#### ✅ Concepts 있을 때 (C++20)

> *Error: constraints not satisfied*
> *... because 'int' is not convertible to 'Song'*
>
> 👉 **장점:** \*\*"int는 Song으로 못 바꿉니다"\*\*라고 정확하고 짧게 이유를 알려줍니다. 함수 내부는 실행조차 안 해보고 입구에서 막았기 때문입니다.

-----

### 4\. 실전 코드 예시

아까 만든 `Album` 코드에 Concepts를 적용해 봅시다.

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <concepts> // C++20 컨셉 헤더

class Song {
public:
    int year;
    std::string title;
    // 생성자 (int, string 2개를 받음)
    Song(int y, std::string t) : year(y), title(t) {}
};

class Album {
    std::vector<Song> songs;
public:
    // [핵심] 모든 인자가 Song으로 변환 가능해야 한다는 제약 조건
    template<typename... Args>
    requires (std::convertible_to<Args, Song> && ...) 
    void addSongs(const Args&... new_songs) {
        (songs.push_back(new_songs), ...);
        std::cout << "노래 추가 성공!" << std::endl;
    }
};

int main() {
    Album myAlbum;
    
    Song s1(2024, "Hello");
    Song s2(2025, "World");

    // 1. 정상 작동 (Song 객체들임)
    myAlbum.addSongs(s1, s2); 

    // 2. 에러 발생 테스트! (주석 해제하면 컴파일 에러)
    // myAlbum.addSongs(s1, 100); 
    // -> 에러 메시지: "int는 Song으로 변환 불가능해서 조건 불만족"
    
    return 0;
}
```

### 요약

1.  **`requires`**: 템플릿의 입구 컷 조건을 겁니다.
2.  **`std::convertible_to`**: 타입 변환이 가능한지 검사하는 표준 도구입니다.
3.  **`&& ...`**: 여러 개의 인자가 들어올 때 "모두 다 조건을 만족해?"라고 물어보는 문법입니다.

이제 C++ 코드를 짤 때 "이상한 데이터가 들어오면 어떡하지?" 하는 고민을 함수 내부(`if`문)가 아니라 \*\*함수 선언부(`requires`)\*\*에서 깔끔하게 해결할 수 있습니다.



# Concepts의 다양한 조건을 거는 방법

C++20의 \*\*Concepts(컨셉)\*\*은 템플릿에 들어오는 데이터 타입을 검사하는 \*\*"컴파일 타임 문지기(Safety Guard)"\*\*입니다.

질문하신 **"정수만 받아라"**, **"특정 함수가 있어야 한다"** 등 다양한 조건을 거는 방법을 체계적으로 정리해 드립니다.

-----

### 1\. 기본: 표준 컨셉 (Built-in Concepts) 사용하기

C++ 표준 라이브러리(`<concepts>`)에는 이미 만들어진 검사 도구들이 많습니다. 가장 많이 쓰이는 것들입니다.

#### ① "정수만 받아라" (`std::integral`)

실수(`float`, `double`)나 문자열이 들어오면 에러를 냅니다.

```cpp
#include <concepts>

// T는 반드시 정수 계열(int, long, short, char 등)이어야 함
template<typename T>
requires std::integral<T> 
T add(T a, T b) {
    return a + b;
}

int main() {
    add(1, 2);       // OK
    // add(1.5, 2.5); // Error: double은 integral이 아님!
}
```

#### ② "실수만 받아라" (`std::floating_point`)

```cpp
template<typename T>
requires std::floating_point<T>
void calculate(T x) { /* ... */ }
```

#### ③ "부모-자식 관계여야 한다" (`std::derived_from`)

특정 클래스를 상속받은 애들만 허용하고 싶을 때 씁니다.

```cpp
// T는 반드시 Song 클래스를 상속받은 자식이어야 함
template<typename T>
requires std::derived_from<T, Song>
void processSong(T song) { /* ... */ }
```

-----

### 2\. 심화: "특정 멤버 함수/변수가 있어야 한다" (Custom Concepts)

이것이 Concepts의 꽃입니다. **"네가 무슨 타입인지는 상관 안 해. 대신 `play()`라는 함수는 꼭 가지고 있어야 해\!"** (이것을 덕 타이핑(Duck Typing) 검사라고도 합니다.)

이때는 직접 \*\*Concept(개념)\*\*을 정의해야 합니다.

#### 시나리오: `play()` 함수가 있는 객체만 받고 싶다.

```cpp
#include <iostream>
#include <concepts>

// 1. 나만의 컨셉 정의: "Playable"
// T 타입의 객체 t가 있을 때, t.play() 코드가 컴파일 가능해야 한다.
template<typename T>
concept Playable = requires(T t) {
    t.play(); // 이 코드가 유효해야 함
};

// 2. 컨셉 적용
// Playable 컨셉을 만족하는 T만 받겠다.
void musicPlayer(Playable auto& item) {
    item.play();
}

// 3. 테스트용 클래스들
class Mp3 {
public:
    void play() { std::cout << "MP3 재생 중..." << std::endl; }
};

class Image {
public:
    void show() { std::cout << "이미지 보여줌" << std::endl; }
    // play() 함수 없음!
};

int main() {
    Mp3 m;
    Image i;

    musicPlayer(m); // OK: Mp3는 play()가 있음
    // musicPlayer(i); // Error: Image는 Playable 조건을 만족 못 함 (play 없음)
}
```

**[문법 설명]**

  * `concept 이름 = requires(T t) { ... }`: T 타입의 가짜 객체 `t`를 가지고 중괄호 안의 코드를 시뮬레이션해봅니다. 만약 컴파일 에러가 나는 코드가 있다면 조건 불만족(`false`)이 됩니다.

-----

### 3\. 조합: 조건 여러 개 섞기 (`&&`, `||`)

논리 연산자를 사용해 복잡한 조건을 만들 수 있습니다.

```cpp
template<typename T>
// 정수이거나(OR) 실수여야 함
requires std::integral<T> || std::floating_point<T>
T add(T a, T b) {
    return a + b;
}

template<typename T>
// 정수이면서(AND) 크기가 4바이트 이상이어야 함
requires std::integral<T> && (sizeof(T) >= 4)
void heavyMath(T a) {
    // ...
}
```

-----

### 4\. 문법 정리 (어디에 적어야 할까?)

C++20에서는 `requires`를 적는 위치가 다양합니다. (취향 차이이나, 2번이 가장 최신 스타일입니다.)

**스타일 1: `template` 뒤에 `requires` (가장 명시적)**

```cpp
template<typename T>
requires std::integral<T>
void func(T a) {}
```

**스타일 2: 타입 이름 대신 컨셉 이름 쓰기 (추천 ⭐)**
`typename` 대신 컨셉 이름을 바로 박아버립니다. 가장 짧고 읽기 좋습니다.

```cpp
void func(std::integral auto a) {} // 매개변수가 하나일 때 (C++20 단축 문법)

template<std::integral T> // 템플릿 쓸 때
void func(T a) {}
```

**스타일 3: 함수 뒤에 `requires` (조건이 길 때)**

```cpp
template<typename T>
void func(T a) requires std::integral<T> && (sizeof(T) > 1) {}
```

-----

### 5\. 한눈에 보는 요약 (Cheat Sheet)

| 상황 | 코드 예시 |
| :--- | :--- |
| **정수만** | `requires std::integral<T>` |
| **실수만** | `requires std::floating_point<T>` |
| **둘 다 가능** | `requires std::integral<T> || std::floating_point<T>` |
| **특정 타입으로 변환 가능** | `requires std::convertible_to<T, Song>` |
| **특정 함수 존재 여부** | `concept HasPlay = requires(T t) { t.play(); };` |
| **여러 인자 모두 검사** | `requires (std::integral<Args> && ...)` (Fold Expression) |

이제 필요한 안전장치를 마음대로 골라서 함수에 걸어두시면 됩니다. 어떤가요? 이 정도면 **C++20 Concepts**를 실무에서 사용하는 데 충분할 것입니다.
